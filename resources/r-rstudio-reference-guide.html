1. Anatomy of a Line of R Code

Here's one real line of R code you'll write during the Module 07 wrangling activities — the kind that counts a child welfare caseload by county. Every colored piece below is explained in the matching-colored card underneath. Same idea as a diagrammed sentence: color ties a piece of code to its explanation.

gcbs_data |>
  filter(state == "GA") |>
  group_by(county) |>
  summarize(n_cases = n())

gcbs_data — the data frame you're starting from. Just a name; it's whatever you called your dataset when you imported it (see Section 5).

|> (the pipe) — reads as "and then." It takes what's on its left and feeds it into the next line as the first ingredient. Chains steps into one readable sentence instead of nesting parentheses. Type it with Cmd/Ctrl + Shift + M.

filter(state == "GA") — keep only the rows where this condition is true. Note the double equals sign (==) — that's "is equal to," a question. A single = would try to assign a value instead.

group_by(county) — from here on, do everything separately for each county, like sorting a stack of case files into piles before counting each pile.

summarize( ... ) — collapse each group (each county's pile) down to one summary row. Parentheses wrap what's inside; R runs the innermost logic first.

n_cases = n() — the actual summary: create a new column called n_cases, set equal to n() (a function that just counts rows). A single = here is correct — inside a function call, = assigns a value to a named argument, it doesn't ask a question.

Notice == vs. = shows up twice above with two different jobs — that trips up almost everyone at first. If a script throws an error, check that one character before anything else.

2. The Four RStudio Panes

When RStudio/Posit Cloud opens, the window is divided into four quadrants. Same color-matching idea as above — each quadrant's label below matches its explanation card.

Source your_script.R
Environment / History gcbs_data   1,204 obs.
Console >
Files / Plots / Packages / Help / Viewer tabs along the bottom-right

Source (top-left) — where you write and save code as a file (a .R script or .Rmd Markdown document). Nothing here runs until you tell it to (Section 6). This is your permanent, reusable work.

Environment / History (top-right) — every dataset and variable currently loaded in memory, and what you've typed before. If a dataset you imported isn't listed here, R doesn't know it exists yet.

Console (bottom-left) — where code actually executes and results print. You can type directly here for a quick one-off check, but anything typed only in the Console is gone when you close RStudio — it isn't saved anywhere.

Files / Plots / Packages / Help / Viewer (bottom-right) — five tabs sharing one space. Plots is where your Module 08 ggplot2 visualizations appear; Packages is where you can see (and check off) what's installed; Help answers "what does this function actually do?" — type ?filter in the Console to jump straight there.

3. R Syntax Basics

Assignment: putting a value in a box ▸
county_count <- 159

The arrow <- means "store this value in a named box." Read it right-to-left: "159 goes into county_count." Most R style guides prefer <- over = for assignment (even though = also works) — type it fast with Alt/Option + –. Box names are case-sensitive and can't start with a number or contain spaces; use underscores instead (county_count, not county count).

Vectors and data frames ▸

A vector is a list of values of the same type, built with c() (short for "combine"):

counties <- c("Fulton", "DeKalb", "Cobb")

A data frame is a whole spreadsheet in memory — rows are cases, columns are variables, and every column is its own vector. gcbs_data in the examples above is a data frame. This is the shape almost everything in the course (AFCARS, NCANDS, GCBS) comes in.

4. Packages

Base R can do a lot, but most of what this course uses — tidyverse, haven, psych — are packages: extra toolkits other people wrote and shared. Two separate steps, and beginners often only do one:

1

Install it (once, ever)

install.packages("tidyverse")

Downloads the toolkit from CRAN onto your computer/cloud instance. You do this once per package, not every session.

2

Load it (every session)

library(tidyverse)

Tells this session "I want to use it now." Do this at the top of every script, every time — installing doesn't mean it's active.

Most common beginner error: "could not find function" almost always means you skipped step 2 this session — not that the package isn't installed.

5. Working Directory & Projects

Your working directory is the folder R looks in first when you ask it to open or save a file. Getting this wrong is the #1 reason "file not found" errors happen when a file is sitting right there.

getwd() # check where R is currently looking
setwd("~/cusw415-project") # tell it to look somewhere else

The Module 07 recommendation: skip setwd() entirely and start every project through File → New Project instead. An RStudio Project (.Rproj file) automatically sets the working directory to wherever the project lives, every time you open it — no path to get wrong, and it's the setup used for Data Science Activity #8 ("organizing your project files").

6. Writing & Running a Script

A script is just a plain text file of R code, saved with a .R extension, that you can re-run any time instead of retyping everything in the Console.

New script

File → New File → R Script, or Cmd/Ctrl + Shift + N

Run one line

Cursor on the line, then Cmd/Ctrl + Enter

Run the whole script

The "Source" button, top-right of the Source pane

Save often (Cmd/Ctrl + S) — unlike the Console, a saved script survives closing RStudio.

7. R Markdown

A regular .R script is code only. An R Markdown document (.Rmd) mixes code with regular writing — useful for the Module 09 capstone write-up, where you want your analysis and your explanation of it in the same file. Three parts:

YAML header — the block between --- lines at the very top, setting the title, author, and output format (e.g., output: html_document).

Regular text — written in Markdown formatting (**bold**, *italic*, # headings) outside any code block.

Code chunks — fenced by three backticks and {r}, e.g. ```{r} … ```. Code inside runs and its output (a table, a plot) gets embedded right there in the final document.

Click Knit at the top of the Source pane to turn the whole thing into a finished HTML, PDF, or Word document.

8. tidyverse Core Verbs

tidyverse isn't one package — it's a bundle of packages (including dplyr and ggplot2) built around one shared idea: data should be organized as rows = cases, columns = variables, and a handful of verbs should cover almost everything you'd want to do to it. These are the six you'll use in Modules 07–08.

VerbDoes what
filter()keeps rows matching a condition
select()keeps only specific columns
mutate()creates a new column from existing ones
group_by()splits data into groups for the next step
summarize()collapses each group into one summary row
arrange()sorts rows by a column's value

The Section 1 example above is filter() + group_by() + summarize() chained with the pipe — the most common pattern you'll write all semester.

9. haven — Importing SPSS/Stata/SAS Files

Federal child welfare data (AFCARS, NCANDS) is often distributed as an SPSS file (.sav) rather than a spreadsheet. The haven package reads those formats directly into R as a normal data frame.

library(haven)
afcars_data <- read_sav("afcars_2023.sav")

Matching functions exist for other formats: read_dta() for Stata, read_sas() for SAS. Same pattern every time — the function name tells you which format it expects.

10. psych — Descriptives & Psychometrics

The psych package gives quick, readable summary statistics in one line — useful for the Module 09 capstone's first look at a variable before any deeper analysis.

library(psych)
describe(gcbs_data$age)

describe() returns mean, standard deviation, min/max, and more in one readable table — faster than calling mean(), sd(), min(), and max() separately. If your capstone research question involves a multi-item scale, alpha() calculates Cronbach's alpha (a reliability statistic) the same way.
